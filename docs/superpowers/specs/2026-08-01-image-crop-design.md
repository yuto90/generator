# アップロード画像の自由トリミング機能 設計

## 背景と目的

現在の各ジェネレーターは、アップロード画像を表示枠の中央基準で自動トリミングしている。そのため、中央以外にある人物やロゴが切れる場合がある。

利用者が画像内の任意範囲をマウス、タッチ、キーボードで選択し、プレビューと保存画像へ同じ結果を反映できる共通機能を追加する。選択範囲の縦横比は固定せず、適用先と比率が異なる場合は画像を変形せず黒または白の余白で補う。

## 対象範囲

初版では現在の全画像入力を対象とする。

- Music Player、Apple Music、YouTube Music、Spotify の正方形カバー
- Instagram Reel の9:16背景
- Instagram Reel の正方形アイコン

回転、反転、フィルター、注釈、画像の永続保存は対象外とする。

## 採用方式

自由比率、ドラッグ・リサイズ、タッチ、キーボード操作を提供する `react-image-crop` を利用する。Cropperの操作ロジックは共通化し、各アプリは画像の入力値と表示スタイルだけを扱う。

画像の切り抜き結果はCanvasからPNG Data URLとして生成する。余白は画像自体へ焼き込まず、各プレビュー枠の背景色と `background-size: contain` で表現する。これにより、同じ切り抜き画像を異なるサイズの枠でも使用できる。

## 共通インターフェース

`src/shared/image-crop/` に型、フィールド、ダイアログ、Canvas変換、表示スタイル生成を配置する。

```ts
type ImageMatteColor = 'black' | 'white';

interface EditableImage {
  originalSrc: string | null;
  displaySrc: string;
  fit: 'cover' | 'contain';
  crop?: PercentCrop;
  matteColor: ImageMatteColor;
}

interface ImageCropFieldProps {
  id: string;
  label: string;
  value: EditableImage;
  targetAspect: number;
  onChange: (value: EditableImage) => void;
  helpText?: string;
  error?: string;
}
```

- `originalSrc` は再編集に使うアップロード元画像を保持する。組み込みのデフォルト画像では `null` とし、調整ボタンを無効にする。
- `displaySrc` はプレビューへ表示する元画像または切り抜き後のPNGを保持する。
- `fit: 'cover'` は未調整の従来表示、`fit: 'contain'` は調整後の余白付き表示を表す。
- `crop` は再編集時に復元できるパーセント単位の選択範囲とする。
- `targetAspect` は初期選択と固定比率プレビューに使用し、選択枠自体の比率は固定しない。

共通のスタイル生成関数は、`displaySrc`、`fit`、`matteColor` から `backgroundImage`、`backgroundSize`、`backgroundPosition: center`、`backgroundRepeat: no-repeat`、`backgroundColor` を返す。既存の画像表示要素はこのスタイルを利用し、DOM構造と装飾を維持する。

## 操作フロー

1. 画像を選択すると、`originalSrc` と `displaySrc` を同じData URLで初期化する。
2. 選択直後は `cover center` で表示し、操作なしでも現在と同じ中央トリミングを維持する。
3. 利用者が「トリミングを調整」を押すと、モーダルダイアログを開く。画像選択前はボタンを無効にする。
4. 初回は、画像内に収まる最大の `targetAspect` の範囲を中央へ配置する。再編集時は保存済みの選択範囲と余白色を復元する。
5. 利用者は選択範囲の内部、辺、四隅をドラッグし、移動と自由比率のリサイズを行う。最小選択サイズは表示上32px四方とする。
6. ダイアログ内の固定比率プレビューは、ドラッグまたはリサイズ完了時に更新する。比率差は選択中の黒または白で表示する。
7. 「完了」で切り抜きPNG、選択範囲、余白色を反映し、`fit` を `contain` へ変更する。
8. 「キャンセル」またはEscでは編集前の値を維持する。「中央に戻す」は対象比率の中央選択へ戻し、余白色は維持する。
9. 各アプリの既存の「適用してプレビュー」で編集中の値を適用済み値へコピーする。

余白色は黒を初期値とし、ダイアログ内で白へ切り替えられる。切り抜き画像と適用先の比率が同じ場合、余白は表示されない。

## 画像生成と制限

Canvas変換では表示上の選択座標を元画像の自然サイズへ換算する。元画像より拡大せず、長辺4,096pxかつ総画素数16,777,216以下となるよう、必要な場合だけ縦横比を保って縮小する。

入力形式は既存どおり `image/*` とする。ファイルの読み込みに失敗した場合は入力欄へ、ダイアログ内での画像デコードまたはCanvas変換に失敗した場合はダイアログへ日本語のエラーを表示する。ダイアログ内の失敗時は「完了」を無効にし、いずれの場合も既存の適用済み画像は変更しない。

生成済みのPNGはローカルのReact状態だけに保持する。サーバーへの送信やブラウザストレージへの保存は行わない。

## ダイアログとアクセシビリティ

モーダルはネイティブの `<dialog>` を使用し、表示中は背後の操作を抑止する。開いた要素へフォーカスを戻し、Escはキャンセルとして扱う。画像選択範囲、余白色、各ボタンには日本語のラベルを付ける。

`react-image-crop` のPointer Eventsとキーボード操作を利用し、マウスとタッチの両方へ対応する。ダイアログは狭い画面でも画像、操作ボタン、固定比率プレビューを縦に配置してスクロールできるようにする。

## プレビューと保存

`useCapture` は変更しない。切り抜き画像、`contain`、余白色はキャプチャ対象DOMへ直接反映されるため、`html-to-image` が画面と同じ状態をPNG化する。

Instagram Reelの同一アイコンを使う2箇所には同じ `EditableImage` と表示スタイルを適用し、両方の切り抜き結果を一致させる。

## テストと受け入れ条件

### 単体・コンポーネントテスト

- 初回選択範囲を対象比率で中央に配置する。
- 自由比率のパーセント選択範囲を元画像座標へ正しく変換する。
- 長辺と総画素数の上限を守り、元画像を拡大しない。
- 未調整時は `cover`、完了後は `contain` と選択した余白色を返す。
- 黒が初期値で、白へ切り替えられる。
- キャンセル、Esc、中央に戻す、再編集が定義どおり動作する。
- 読み込みまたはCanvas変換に失敗した場合、値を更新せずエラーを表示する。
- 全6画像入力が共通フィールドを使用し、既存の適用操作でカードへ反映される。
- キャプチャ対象要素にプレビューと同じ画像URL、表示方式、余白色が設定される。

### ブラウザ確認

- SafariとChromium系ブラウザで辺、四隅、内部のマウスドラッグを確認する。
- レスポンシブ表示でタッチ相当のPointer操作、ダイアログのスクロール、Escとフォーカス復帰を確認する。
- 正方形、9:16、それ以外の自由比率について黒と白の余白を確認する。
- 各ジェネレーターで画面プレビューと保存PNGが一致することを確認する。

最終確認として `npm test` と `npm run build` を実行する。
