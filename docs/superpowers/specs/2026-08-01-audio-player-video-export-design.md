# 音声プレーヤー動画出力 設計

## 背景と目的

Issue #31 の対象である4つの音声プレーヤーから、ローカル音源と同期した再生画面をMP4として保存できるようにする。

- Music Player
- Apple Music
- YouTube Music
- Spotify Style

既存のPNG保存とYouTubeプレビューは維持する。動画生成はブラウザ内だけで完結させ、音源や画像をサーバーへ送信しない。

## 確定した仕様

### 動画範囲

- ユーザーは動画の開始位置を `m:ss` で指定する。
- 開始位置入力とカード上の再生位置スライダーは相互に同期する。
- 出力時間は `min(30秒, 音源時間 - 開始位置)` とする。
- 音源末尾まで30秒未満の場合は曲末で終了し、残り1秒以上なら短い動画を許可する。
- 開始位置が不正、音源時間以上、または残り1秒未満の場合は生成しない。
- プレビューと出力では、同じ開始位置、終了位置、進捗計算を使う。

### 音源

- 動画出力にはローカル音源ファイルを必須とする。
- ファイル入力は `audio/*` を受け付け、MP3、M4A、WAVを代表形式として確認する。
- 実際の対応可否はブラウザでデコードを試して判定し、未対応形式は理由を表示する。
- ローカル音源を選択している間は、プレビュー再生にも同じ音源を使う。
- YouTube URLは既存のプレビュー専用とし、YouTube音声を動画へ取り込まない。
- 動画の音量にはカード上の音量設定を反映する。

YouTube APIのコンテンツを分離、保存、再合成する方式は採用しない。これはYouTube API Services Developer Policiesのダウンロードおよび音声・映像分離に関する制約を守るためである。

### 出力形式

- 出力はMP4、映像はH.264、音声はAACとする。
- フレームレートは30fps、カード部分だけを出力する。
- 出力幅は1080px固定とし、カードの縦横比を維持する。
- 出力高さはH.264の要件に合わせて最も近い偶数へ丸める。
- ファイル名は各アプリIDに対応した `<app-id>.mp4` とする。
- 正式対応ブラウザはChromeとSafariとする。バージョン文字列ではなく、実行時のH.264/AACエンコード可否で判定する。
- H.264またはAACを生成できない環境では保存ボタンを無効化し、非対応理由を表示する。WebMなど別形式へのフォールバックは行わない。

## UI設計

既存サイドパネルの保存領域を「画像」「動画」のタブに分ける。初期タブは既存動作を維持するため「画像」とする。

「画像」タブには現在の「画像として保存」をそのまま残す。「動画」タブには次を上から表示する。

1. 動画用音源ファイル
2. 動画開始位置 `m:ss`
3. 出力範囲。例: `1:20–1:50`
4. 出力情報: `MP4・30fps・幅1080px`
5. Chrome/Safariの対応状態
6. 「動画をプレビュー」
7. 「MP4として保存」

動画タブ内には「YouTube音声は動画へ出力されません」と常時表示する。

「動画をプレビュー」は開始位置からローカル音源を再生し、計算済みの終了位置で自動停止する。プレビュー中も開始位置入力とスライダーは再生位置に合わせて更新する。停止後は開始位置へ戻し、繰り返し同じ範囲を確認できるようにする。

## コンポーネント構成

### 表示カード

4アプリそれぞれのカード部分を、フォームや音源制御を持たない表示専用コンポーネントへ分離する。画面プレビューと画面外の動画生成面は同じコンポーネントを使う。

表示専用コンポーネントには次の共通フレーム情報を渡す。

```ts
interface PlayerFrameState {
  currentTime: number;
  duration: number;
  progress: number;
  playing: boolean;
  volume: number;
}
```

タイトル、アーティスト、アートワーク、色など既存のアプリ固有表示値は、各カードの既存propsとして渡す。動画生成中は `playing: true` とし、再生アイコン、進捗、時刻、Apple Musicの再生中アートワーク状態を動画へ反映する。

### 共通動画モジュール

`src/shared/video/` に次の責務を集約する。

- ローカル音源の読込、メタデータ取得、再生、停止、シーク、Object URLの破棄
- 開始位置の解析と動画範囲計算
- H.264/AACエンコード可否の判定
- 動画プレビューの開始と終了位置での自動停止
- フレーム生成、音声切り出し、MP4生成、ダウンロード
- 生成進捗、キャンセル、失敗、再試行の状態管理

主要な共通型は次とする。

```ts
interface VideoClipRange {
  start: number;
  end: number;
  duration: number;
}

type VideoExportPhase =
  | 'idle'
  | 'preparing'
  | 'rendering'
  | 'muxing'
  | 'completed'
  | 'failed'
  | 'cancelled';
```

範囲計算は副作用のない `calculateVideoClipRange(audioDuration, start)` とし、4アプリとテストから共用する。

## 動画生成フロー

1. 音源選択時にObject URLを作り、`HTMLAudioElement`で時間を取得する。音源変更・アンマウント時は古いURLを破棄する。
2. MP4保存時に開始位置、残り時間、ブラウザのH.264/AAC対応を再検証する。
3. `AudioContext.decodeAudioData()` で音源をデコードし、開始位置から終了位置までを切り出す。`OfflineAudioContext`で音量を適用し、48kHz、最大2チャンネルへ正規化する。
4. 表示専用カードを画面外の描画可能な領域へマウントする。`display: none` は使わない。
5. `document.fonts.ready` を待ち、各フレームで `currentTime = start + frameIndex / 30` を計算する。
6. フレーム情報をカードへ反映し、描画完了後に `html-to-image` の `toCanvas` でカードをキャンバス化する。拡大率は出力幅が1080pxになる値を使う。
7. Mediabunnyの `CanvasSource` へ各フレームを時刻順に追加し、エンコーダーのバックプレッシャーを待つ。最終フレームの時間は動画終了位置を超えないよう短縮する。
8. 切り出した音声を `AudioBufferSource` へ追加する。
9. `Mp4OutputFormat` と `BufferTarget` でMP4を完成させ、Blob URLからダウンロードする。ダウンロード後はBlob URLを破棄する。

動画は最大30秒のため、初期実装ではSafariでも利用できる `BufferTarget` を採用する。ファイルシステムAPIへのストリーミングは対象外とする。

## 状態、キャンセル、エラー

生成中はフォーム、タブ切替、プレビュー、画像保存、動画保存を無効化し、次の進捗を表示する。

- 準備中
- フレーム生成中。生成済みフレーム数から進捗率を計算する
- 音声合成中
- MP4仕上げ中

生成中はキャンセルボタンを表示する。キャンセル要求はフレームごとに確認し、Mediabunnyのソース、AudioContext、画面外カード、Object URLを解放する。途中ファイルはダウンロードしない。

エラーは次の区分で日本語表示する。

- 音源未選択
- 開始位置の形式不正または範囲外
- 音源の読込・デコード失敗
- H.264/AAC非対応
- カードのフレーム生成失敗
- MP4生成失敗

失敗時は入力、音源、開始位置を保持し、「もう一度生成」で生成処理だけを再実行する。メッセージには、音源や開始位置の修正が必要な場合はその操作を、生成処理だけの失敗なら再試行操作を明示する。

成功時は実際の出力時間とファイル名を表示する。

## テスト計画

### 自動テスト

- `calculateVideoClipRange`
  - 開始0秒、曲中、残り30秒、残り1秒、残り1秒未満
  - 30秒上限と曲末短縮
  - 不正値、負数、音源時間以上
- 開始位置の `m:ss` 解析とスライダー同期
- 30fpsのフレーム時刻、最終フレーム、偶数の出力高さ
- 音量適用と切り出し範囲
- コーデック非対応、キャンセル、失敗、再試行の状態遷移
- 4アプリの画像／動画タブ、ローカル音源優先、既存PNG保存

ブラウザ依存APIとMediabunnyはVitestで境界をモックし、タイムラインと状態遷移を決定論的に検証する。

### 実ブラウザ確認

ChromeとSafariで、MP3、M4A、WAVを使って次を確認する。

- 4アプリすべてで任意位置からMP4を保存できる
- 30秒出力と曲末で短縮される出力を再生できる
- カードの見た目、進捗、時刻、再生中状態がプレビューと一致する
- 映像と音声の開始ずれが100ms以内
- ファイル時間の誤差が1フレーム以内
- 生成中の進捗とキャンセルが機能し、再試行できる
- PNG保存とYouTubeプレビューに回帰がない

最終確認として `npm test` と `npm run build` を実行する。

## 受け入れ条件

- 対象4アプリから、ローカル音源付きのMP4をカード範囲で保存できる。
- 開始位置は入力とスライダーで指定でき、出力は最大30秒、曲末では1秒以上の範囲まで短縮される。
- 出力は幅1080px、30fps、H.264/AACのMP4である。
- プレビューと出力が同じタイムラインと表示状態を使う。
- ChromeとSafariで、対応可否、出力形式、YouTube音声が対象外であることを画面で確認できる。
- 失敗時に原因と修正または再試行方法が表示される。
- 既存のPNG保存とYouTubeプレビューが維持される。

Issue #31の従来の「15〜30秒の範囲外の長さにならない」は、「通常30秒、曲末では1秒以上30秒未満へ短縮可能」に更新する。

## 対象外

- YouTube音声のダウンロード、分離、動画への再合成
- WebMなどMP4以外の出力
- Firefox、EdgeなどChrome/Safari以外の正式対応
- 9:16背景、余白、装飾を含むSNS向けキャンバス
- サーバーサイドレンダリング、クラウド保存、生成履歴
- 30秒を超える動画、音源ループ、曲末後の無音追加
